---

## 2. Документація по розробленому веб-застосунку

### Призначення застосунку
**Simple Inventory API** — це RESTful веб-застосунок для базового управління інвентарем. Він дозволяє зберігати інформацію про товари (назва, кількість) у базі даних, створювати нові записи та переглядати існуючі за допомогою HTTP-запитів.

### Налаштування середовища (Development)

Для локальної розробки або тестування поза віртуальною машиною необхідно:

1. Встановити Node.js (v18+) та npm.
2. Встановити MariaDB/MySQL та створити локальну базу даних.
3. Клонувати репозиторій та виконати команду:
   npm install
4. Створити файл .env у корені проекту та вказати рядок підключення до БД:
DATABASE_URL="mysql://USER:PASSWORD@localhost:3306/inventory_db"
5.Виконати міграцію для створення таблиць:
npx prisma migrate dev
6. Запустити командою : node index.js --port 8000

---

### 3. Документація по API-ендпоінтах

**Застосунок надає наступні маршрути:**

Бізнес-логіка (Публічні маршрути):
GET / — Головна сторінка (HTML-інтерфейс із посиланнями).
GET /items — Отримання списку всіх товарів (підтримує формати HTML та JSON).
GET /items/:id — Отримання детальної інформації про конкретний товар за його ID.
POST /items — Створення нового товару. Очікує JSON-тіло: {"name": "string", "quantity": number}.

Службові маршрути (Доступні лише локально):
GET /health/alive — Liveness probe. Повертає 200 OK (перевірка, що процес Node.js живий).
GET /health/ready — Readiness probe. Повертає 200 OK, якщо є успішне з'єднання з базою даних MariaDB, інакше 500 Database connection failed.

## 1. Індивідуальне завдання та архітектура
У рамках виконання роботи реалізовано багатовузлову інфраструктуру для веб-застосунку згідно з розрахунковим варіантом:
* **Тематика:** Simple Inventory (Сервіс обліку обладнання)
* **База даних:** MariaDB
* **Порт застосунку:** 8000.
* **Архітектура:** 2 віртуальні машини (Worker Node та Database Node).

Система маршрутизації побудована наступним чином: `Клієнт -> Nginx (Reverse Proxy, :80) -> Web App (Node.js, :8000) -> MariaDB (:3306)`Доступ до БД жорстко обмежений і дозволений виключно з Worker-ноди

## 2. Документація веб-застосунку (API)
Застосунок реалізує наступні REST API ендпоінти:
* `GET /items` — виведення списку всіх предметів в інвентарі.
* `POST /items` — створення нового запису (приймає `name`, `quantity`).
* `GET /items/<id>` — детальна інформація про конкретний запис.

**Health Checks (Перевірка стану):**
* `GET /health/alive` — перевірка працездатності самого сервісу (повертає HTTP 200 OK)
* `GET /health/ready` — перевірка успішного підключення до бази даних (повертає HTTP 200 OK)

## 3. Інфраструктура та середовище розгортання
Розгортання здійснюється на офіційних Cloud-образах Ubuntu 
* **Гіпервізор:** KVM/QEMU (провайдер libvirt)
* **Ресурси:** Мінімальні вимоги для кожної ВМ (1 vCPU, 1024 MB RAM, 10 GB Disk).

### Користувачі системи та їхні права:
* `ansible` — автоматизація (безпарольний доступ через SSH-ключ).
* `teacher` — перевірка роботи (пароль: `12345678`, повний sudo доступ).
* `operator` — керування сервісами (пароль: `12345678`, обмежений sudo доступ лише для рестарту `mywebapp` та `nginx`).
* `app` — системний користувач (без можливості логіну), від якого працює Node.js бекенд.
